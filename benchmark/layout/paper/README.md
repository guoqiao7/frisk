# Frisk 论文回归基线

2026-11-25，物理 GPU0，NVIDIA H100 PCIe，114 SM。源代码基线为 `58d16b3`，整理后的编译实现为 `4af412a`，测试修订为 `9093ba6`。发布分支为 `paper/h100-layout-pipeline`。所有表内时延均在 GPU0 重新采集，单位为微秒。完整机器、版本、编译器指纹及测试状态见 [validation.json](validation.json)。

## 论文可以支持哪些结论

**局部最优约束与选择。** C2 SS 保留 `1×2`、`2×1`，RS 唯一为 `2×1`。把一个独立转置分支放到 MMA 前后，解集一致。54 个冻结的三方 C2 内核按计算模式、消费者、锚点与实际映射分成 24 组，组内 cubin 哈希全部一致。RS 加列归约的开放回放中，Frisk 保住唯一的 `2×1`（25.480 µs），TileLang 选 `1×2`（20.044 µs）。这个反例给出了锚点局部最优约束在整图时延上的代价。混合图的 `64×16` 转置加独立 dim0 Sum 在两个分支顺序下均由 655 降到 543，这是静态代价。

**消费者确实可以改变生产选择。** 在 `256×512×256`、132 CTA、K16、固定驻留宽度和直接交付下，仅写 C 选 `2×1` 的 64 行交错分块，149.280 µs；再输出列和选 `1×2`，160.411 µs；改为行和也选 `1×2`，144.896 µs。三个选择分别是各自图上的最快合法锚点。32 CTA 时三图都选交错分块。开放分片和交付后，六个选中内核的 cubin 都与固定实验中相应内核一致。六个既有留出 shape、三种消费方式、两个网格，共 36 项；当前首选命中 30 项，选择损失 P95 为 1.59%。最大损失 7.39%，为 `512×512×208`、32 CTA 的行和。详见 [生产锚点逐项表](native-anchor.csv)。

**四臂划清了 B 复用和写回的贡献。** 冻结连续分块候选，交叉固定或开放锚点与直接或独立选择交付，分别固定两种 B 复用策略。三个图、两个网格得到 48 行配置，每行有 62 个配对块。旧评分选中 24/48 个当轮最快配置。写回指令成本修正后，对应的冻结选择在相同 cubin 池中命中 48/48。以列和、132 CTA、开放两项为例，禁用 B 复用时修正后的 `2×1` 直接交付为 171.242 µs，旧选择为 205.792 µs；启用复用时修正后的 `1×2` 为 161.422 µs，旧选择为 192.070 µs。这里两种 B 策略内的最优方向对三个图一致。完整消融与上述允许交错分块的生产实验具有不同候选域。[四臂消融](consumer-ablation.csv)

**固定流水线的三方收益依赖消费者与工作量。** `128×512` 的 GEMM 加列最大值，K80 时 Frisk、Triton、TileLang 分别为 27.883、30.032、47.344 µs；K272 时为 59.291、59.520、83.867 µs。`128×256×128` 反例中，Frisk 为 25.979 µs，TileLang 为 24.155 µs。归一化中，`64×128` LayerNorm 选连续 4，`16×512` Softmax 保留原布局，`64×1024` RMSNorm 选连续 1，`128×256` LayerNorm 保留原布局，两个网格结果一致。`16×256` RMSNorm 的额外复用实验中，8 个输入、输出地址轮换与网格组合的静态选择全部命中对应池的最快 cubin。[三方逐项数据](threeway.csv) · [输入、输出复用实验](normalization-reuse.csv)

**FA 整栈与固定流水线应分别引用。** D64 普通与 causal、6 个序列长度、3 种固定顺序的 36 行冻结布局回放中，Frisk 与较快对手的配对时延差全部在 ±2% 内。原生内核的 GQA D64 普通 `N920 H15/1` 三方中位数为 14.843、16.496、22.843 µs；D128 causal `N1025 H7` 为 18.523、25.979、20.240 µs。D64 MHA 的 `N256 H2` 普通与 causal 分别比当轮更快对手慢 2.55%、2.35%。整栈结果同时受分块、搬运、发射顺序和写回影响。D64 causal `N116 H54` 及 GQA `N920 H15/1` 的静态、调优入口逐位输出一致，并通过了布局、执行契约和 cubin 身份检查。D128 普通 `N193 H4` 默认只编译一个有保护的寄存器写回内核，最大绝对误差为 0.000261 以内。

## 如何读表与复核

- [三方表](threeway.csv) 有 102 行，包括 39 行归一化、逐元素、转置及 GEMM/ReGLU 布局回放，36 行冻结 FA 回放，18 行冻结 C2 回放，4 行 native GEMM 和 5 行 native FA。相同 shape 可出现在多个网格、锚点或顺序中。布局回放使用同一后端；原生结果采用三方各自的合法实现。对手范围为记录中实际通过数值检查的候选池。
- 在 39 行布局和 9 行 native 对照中先以 11 个随机配对块选各家代表，再以独立的 33 块测静态首选和三家筛选首选。冻结 FA、C2 的固定配置直接配对，表中重复的 Frisk 两列表示同一配置。百分比取各块 Frisk 与较快对手之比的中位数，负数表示 Frisk 更快；区间是对已选对手配对块的 bootstrap 95% 区间。两个微秒列的中位数之比可能与配对比值有小幅差异。表中 ±2% 用于描述效应大小。
- [生产锚点表](native-anchor.csv) 在每个图上比较认证为局部同优的全部锚点，分别在 32 和 132 CTA 下测量。选择损失为静态首选中位时延除以该图该网格最快锚点的中位时延，再减一。不同图的绝对时延不能直接作为布局收益。此轮留出集沿用已登记集合。
- [消融表](consumer-ablation.csv) 的 `image/gpu0_us` 是旧评分选择及其本轮时延，`corrected_arm/corrected_us` 是修正评分选出的同一候选集内的内核及其本轮时延，`gpu0_best_arm/gpu0_best_us` 来自重新遍历该实验臂准许的候选。对修正选择核对了两份历史镜像的实际 SHA-256。NCU 复测覆盖 30 个内核启动，全局与 local sectors、共享读写指令见证据包。
- 测试通过 109 项 lit、710 项布局 C++ 单测、65 项选择器 C++ 单测。提供规定的输入夹具后，Python 的 1147 项中通过 1132 项。剩余 13 项涉及旧校准凭据绑定的源内容，另两项要求与历史转换函数 AST 或旧发射字节一致。清理前的相同失败已对照验证，保留旧凭据和失败名称。论文数据的硬件、数值与机器码回归另有独立记录。[验证记录](validation.json)

## 数据与复现

[evidence.tar.gz](evidence.tar.gz) 含配对原始块、选中内核的身份、NCU 报告、生成表格与硬件重测脚本。解压到空目录，在该目录运行 `python summarize.py` 可用 Python 和 NumPy 离线生成四张 CSV。SHA256SUMS 覆盖包内文件。在原 H100 环境运行 `bash reproduce.sh` 会建立独立目录，按 GPU0 的 UUID 选择设备；`bash reproduce.sh --prepare-only` 可检查夹具准备。重测需要服务器已安装的编译器、原始三方推断映射与冻结 cubin，详见包内来源清单。绝对路径、历史大扫、未纳入论文的试跑、其他研究线的封存凭据在服务器上按用途管理。

本轮完整工作目录为 `/data0/baopeihua/frisk-paper-regression-bqxKKZ`。退役实验已从六处原路径删除，恢复包在 `/data0/baopeihua/frisk-withdrawn-58d16b3`。恢复包逐文件解压核对了内容、权限和符号链接目标；删除清单和压缩包哈希见验证记录。
