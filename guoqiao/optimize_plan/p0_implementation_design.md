## 1. 基线与范围

实现前基线为本地 `main` 的 `219c0cf`：`feat: baseline static attention layout inference and audit reports`。包含 Attention/Broadcast/Storage 修复、测试、推断汇报及优化清单，不包含构建产物。

本轮目标：固定真实 Q/K/V/O 外部布局；无需临时诊断程序即可解释选择；在原预算内修复已观察到的单变量替换漏选。

不新增 tile/线程数搜索、warp specialization、MMA 几何候选、动态 shape、通用 reshape、GPU lowering 或 GPU 性能结论。不改九项 CostVector 的含义、字典序和数值模型；默认 exact=256、beam=32、每分量总尝试预算=65536 不变。

已选择方案 A：保留 beam 和部分成本排序，取得合法完整解后进行单变量邻域改进。备选 B 是改造部分成本排序与下界；本轮不实施 B，以免扩大模型接口和下界证明范围。

## 2. O01：固定外部内存契约

保持当前 Attention 语义：SM90a、128 线程，Q/K/V=`64×16xf16`、O=`64×16xf32`；SS QKᵀ、稳定 f32 Softmax、cast_f16、RS PV。保留自由 Storage 布局用例，新增固定外部布局用例。

使用现有 `frisk.storage_contract` 声明完整 Global 根布局；普通根的地址为：

```text
Q/K/V[i,j] = base + 2 × (16 × i + j)
O[i,j]     = base + 4 × (16 × i + j)
```

声明必须支配使用，按共同根验证别名；内部 Shared/Tensor 布局仍由求解器选择。不得预填全部 Tensor 编码、用常量替代中间计算或删除真实 Copy/Store。

必须覆盖：

- 未知更强对齐：Global 根仅保证 1 字节对齐，不得创造额外保证。
- 明确对齐：调用者显式声明 Global 根 16 字节对齐，Shared 保留显式 allocation 对齐；声明是运行前置条件，不是优化器推导出的事实。
- 静态偏移：较大行主序根截取 `64×16` 视图，oracle 包含父根跨度和偏移。例如 `128×16` 根从第 16 行开始，f16 地址为 `base+2×((i+16)×16+j)`。
- 偏移削弱向量化：合法子视图具有非对齐起点时，不得仅凭根对齐接受宽访问；允许标量回退，不要求一定选择异步路径。
- 硬契约冲突：绑定与固定根不一致的 view，必须失败并保留输入 IR。

验收：核对全链 SSA 数据流、四个外部矩阵全部坐标的物理字节地址、根契约与 Tensor 编码；执行实际布局 verifier、print/parse、重复 pipeline 和失败回滚。外部地址在合法优化后不变。

不承诺固定布局例沿用自由布局例的候选数或成本。若暴露缺陷，只修复本链所需通用规则，不增加 Attention 形状特判。

## 3. O03：可选、稳定且有界的 trace

### 3.1 接口

布局推断 pass 和完整 pipeline 新增 `trace-file`，默认空即关闭。保留现有 `stats-file` 语义；trace 为独立报告，`schema_version=1`。

新增 `trace-max-events=4096`、`trace-max-bytes=8388608`；事件数须为正，字节上限至少 4096，非法参数在修改 IR 前报错。预算只限制记录，不改变推断；截断必须显式标记。

顶层记录目标、成本覆盖版本、求解选项、分析/验证状态、attempt、截断计数、最终成本。身份采用稳定编号，不记录裸指针。

### 3.2 内容

1. 图与候选：变量/约束及来源、候选 attribute 与稳定 ID、prepared/strict/common 域变化、指令/归约联合支持关系。
2. 拒绝：变量、候选、约束、阶段、原因；有坐标反例时保留。只有支持表信息时写“当前支持表无支持”，不伪造更具体原因。
3. 搜索：分量、深度、MRV 变量、探测/扩展/保留/淘汰数量；每层最多展示前 4 个保留和前 4 个淘汰状态的 key 与成本。标明部分估计与完整成本，其余状态只计数。
4. 邻域：起始成本、替换变量/旧候选/新候选、验证结果、完整成本、是否接受和停止原因；未展开事件仍计入准确统计。
5. 最终：assignment、指令/归约契约、转换/重计算计划、九项成本分解、未建模说明。

明确区分 Proven、Disproven、Unknown、预算不足、beam 淘汰和合法但未改善。不能把 beam 淘汰写成候选非法。

### 3.3 成本分解与限量

贡献来自现有计费路径，不通过重复求解猜测：普通值按现有寄存器/复制规则计费；Shared 按共同根只计一次跨度；访问、Copy setup、MMA、Reduce 关联实际约束/操作；转换/重计算按共享 leader 计费。

贡献项采用相同九维 CostVector，按既有饱和加法汇总，必须等于完整成本并保留 saturation 标志。截断明细时保留 `omittedCost` 汇总，使“已展开贡献 + 未展开贡献”仍等于总成本；仅在明细未截断时宣称解释完整。

attribute、assignment 和支持表均纳入预算。超限不再追加可选事件，保留固定大小的状态摘要、截断计数与总成本。默认限制下，当前 Attention 应能记录完整阶段域及最终分项成本；不要求保存完整搜索树。

### 3.4 兼容与文件失败

关闭 trace 不构造阶段快照或重算证明。开关 trace 得到相同语义 IR、候选顺序、选择和搜索计数；计时等明确标注的非确定字段之外，重复运行的语义记录稳定。

单份报告采用同目录临时文件加原子替换。写失败给出文件诊断并保留原 IR；与 `stats-file` 同路径则提前拒绝。两份报告不承诺跨文件原子事务；trace 状态仅陈述已完成的分析/验证，不提前宣称 IR 已提交。

验收包含 schema、总成本复核、稳定性、事件与字节截断、路径冲突/写失败、trace 开关等价，以及失败 attempt 的真实分类。

## 4. O02：原预算内的单变量邻域改进

### 4.1 范围与选项

新增 `refine-beam-solution=true`：只作用于进入 beam 模式且已找到合法完整解的分量；关闭可复现旧策略。精确模式保持不变。

新增 `max-refinement-probes=256`：限制每分量邻域尝试数，0 等价于禁用。每次探测同时消耗既有 `max-expanded-states` 剩余预算，总尝试数不超过 65536，不另开隐藏额度。

使用该 attempt 传播后冻结的候选域；不恢复删掉的候选、不修改硬绑定、不生成新布局、不触发额外松弛。

### 4.2 算法

1. 以 beam 最佳合法完整方案及其成本为 incumbent。
2. 按规范变量/候选顺序枚举单变量替换，跳过原候选。
3. 每次尝试计入 refinement probe 和总 expanded attempt；检查分量全部约束。Unknown 不作为合法支持。
4. 对合法邻居计算完整成本，包含重新选择的转换/共享/重计算计划；不只看变量局部成本。
5. 每轮扫描选择严格优于 incumbent 的最佳邻居；相同最佳成本按规范 assignment key 决胜。与 incumbent 成本相等不移动。
6. 接受改善后再扫描；无改善或任一预算耗尽则停止。中途耗尽可接受本轮已验证最佳改善，但不能宣称扫描了完整邻域。
7. 最终 assignment 重建指令契约和边界计划，经既有 solution/实际 IR 验证后物化。

严格下降和有限域防止等价解循环。不能跨越需要同时改变两个变量才能合法的障碍，因此不保证全局最优，也不保证找回所有 beam 漏选。

### 4.3 失败与统计

- 未取得解就耗尽预算：保留既有 SearchBudget/SearchIncomplete 语义。
- 已有合法解但改进预算耗尽：保留解，记录停止原因，不制造硬冲突。
- 合法邻居成本计算失败：返回 CostFailure，不能当作免费方案；IR 回滚。
- 非法或 Unknown 邻居：记录后继续，不降低最终证明要求。

分别记录 MRV probes、expanded nodes、refinement probes、接受次数、扫描轮数、起止成本和停止原因。总 expanded 包含两类探测；旧 MRV 字段仍只统计 MRV。局部改进结束不能把曾截断的 beam 标为 exhaustive。

### 4.4 验收

- 自由布局 Attention 关闭优化重现旧选择；开启后取得不劣于已知 `[8293,576,64,0,428,6144,6,0,0]` 的完整成本并通过实际 verifier，不能只比较第二项。
- 同候选域、同成本模型下，优化后的成功结果不劣于关闭结果；成本失败单独报告。
- 小图精确 oracle 核对成本和合法性，不要求一般局部解等于全局最优。
- 覆盖字典序优先、后续项改善、同成本不移动、非法低成本邻居、需双变量改变的局部最优、转换成本抵消局部收益。
- 覆盖无剩余预算、扫描中途耗尽、多轮改善、候选插入顺序变化、精确模式不变。
