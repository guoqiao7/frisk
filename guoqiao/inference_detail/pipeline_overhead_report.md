# Frisk 任务 2：布局推断全链路开销与执行回归

本轮在 H100 的既定单 CTA 支持域收敛主机开销。矩阵包含 Exp128×64、Mixed512×64、Div512×128，以及弱向量、强对齐 cp.async、强对齐 TMA 三种 Attention ABI；每类都走 J 与充分知情的 LI。12 个池的容量仍为 K4（总上限 48），实际保留 42 个完整候选。搜索仍使用每池 65,536 probe、256 refinement 和一次网络变体预留评分。旧性能标签未进入新决策。

## 实现

1. **地址足迹。** 全局内存按整 32B 平移取等价代表，保持扇区相位及扇区数；共享内存按整 4B 平移，bank 编号只作循环置换，保持冲突数。原地址合法性、溢出、所有权、访问指令与 ALU 计费仍分别检查。仅计算当前地址空间需要的指标，每个构建器最多保存 256 个足迹。独立旧集合实现对照覆盖广播、读写、掩码、跨字／跨扇区及 uint64 边界。
2. **规划、证明和发射。** 同一候选内共用一次真实发射与有序地址查询观察；需求审计、生存审计和支持检查分别执行原谓词。会话绑定完整执行包、记录、类型化配置、源文件、查询轨迹和结果；消费者获得独立状态，失败证明不作成功缓存。显式登记后才启用，旧独立 API 和旧成本分析器保持原样。42 项逐字节对照将真实发射次数从 150 降到 42，并复用 24 份强证明及 95 行访问事实。
3. **编译和验证。** 原生缓存保持完整源码、工具、编译输入和环境身份。对同一完整安全身份选定确定的实际工具代表，同时把每行回执绑定回自己的当前镜像。首次运行执行一批普通验证与四种 sanitizer；复用时重新执行全部普通数值、ABI、资源、stream、capture 和保护区检查。仅在完整安全证据等价时复用 sanitizer 结果。会话进出全内容复验，内部核对文件身份和集合；假定已登记的本机写入者可信。
4. **成本证据。** 缓存绑定完整源码、类型化输入、实际工具版本、依赖和受控环境。可跨目录复用纯 decoder 与分析事实，各目录的程序和镜像来源独立复验。排序证书缓存只提供提案，核心仍用 Fraction 独立验算，未证明结果不缓存为成功。R16 视图仅更新身份，价格、单位、训练约束、见证、支持域和决策规则不变；严格旧 LOCAL 仍为 6422。

旧 r3 的 42 项生成耗时 478.195 秒，其中需求／存活审计 350.423 秒、固定布局 C++ 回放 68.080 秒。原最大 Div 候选同 CPU、独立进程的生成后段由 69.697 降到 48.274 秒（约 31%）；峰值 RSS 约 1.34 → 1.93 GiB，因为新方案保留候选内密封观察。四并发的 42 项逐字节验收不用于估算加速。

成本证据同样以独立进程复核：原路径 15.996 秒，新路径首次 14.492 秒、同目录热缓存 1.388 秒、新目录 4.605 秒。全部样本证据相同，后两者新增 decoder 调用为零。106 个唯一 CUBIN 的 186 处绑定也核对了受控工具的完整输出。

“首次”指本任务显式缓存为空；未清理 OS 或 Triton 的系统级缓存。两个运行都在新目录重新准备、搜索和发射。表为每阶段一次实测墙钟之和；候选分布来自各自异质请求的观测，不是重复测量置信区间。采样 RSS 为主机进程树之和，可能重复计入共享页，不含显存。内核运行时间没有作为此阶段的测量对象或选择标签。

首次／复用均成功编译或加载并普通验证 42 项，各完成 7878 / 7878 条数值记录。编译 API 调用 30 → 0；原生完整缓存命中 9 → 42。两次编译请求的失败、未尝试数均为零。请求墙钟 p50 为 4.11 / 1.58 秒，p95 为 18.34 / 17.52 秒。两个运行有 30 个唯一 CUBIN 和 33 个安全身份，实际 sanitizer 调用 4 → 0，成本 decoder 调用 60 → 0。采样进程树峰值 12.54 / 12.53 GiB。

42 项的审计、TTGIR、配置、PTX 和 CUBIN 在首次和复用间逐字节相同，成本特征与选择状态一致。Exp、Mixed、Div 的 J／LI 分别保持 c3／c1、c2／c0、c0／c0，12 池逐项决定及证据在全链路验收 JSON。

## 失败、回归与验收边界

- r1 在发现基准内嵌源码清单早于最终缓存源码后中止；r2 严格比对拦住了 Attention 参考日志中缺失的 paid audit 诊断字段。修复后按登记参考复用原诊断参数，没有放宽比较。
- r3 完成 42 项编译及普通验证，但重复安全身份的代表选择与 ordinary 来源记录分别取了首行和末行，导致第一种 sanitizer 之后的来源复验正确拒绝。现统一绑定实际代表，并在每行回执显式重绑当前镜像。r3 保留为失败；最终源码另外执行了两行同镜像、不同来源的 TMA 冷／热复验。
- C++ 707 项 core 与 65 项 selection 通过。证据／适配器 143 项、模型／成本缓存 118 项、发射相关 82 项 Python 回归分别通过（这些集合有重叠，未相加）。任务1与旧 network 封存的 37,755 个文件、约 28.43 GB 全内容复验通过，无元数据漂移；更早索引哈希未变化。
- 验收覆盖此处登记的已知程序和单 CTA 支持域。生产默认仍为 legacy。新性能留出、全域模型晋升和相同算法／ABI／精度／调优预算下的 Triton、TileLang 对比仍属后续阶段。
