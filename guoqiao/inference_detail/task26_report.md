# Task 26 工作汇报：安全扩展候选、提升转换位置、共享重计算

整理日期：2026-09-28。范围：M5 Task 26，采用已确认的方案 A。

本报告依据实际代码、测试及[实施计划](../layout_inference_implementation_plan.md) §26.1–26.5 整理。验收数字引用实现结束时的记录，本次整理报告未重新运行测试。下文程序均为解释用伪代码，实际回归入口列在文末。

## 1. Task 26 完成了什么？

一句话概括：**在不改变程序硬约束的前提下，候选确实不足时有序补充候选；已有合法方案时，减少重复布局转换和重复重计算。**

这里的“布局转换”不是改变张量的数值，而是改变元素由哪个线程、哪个寄存器持有；“重计算”是直接按消费者需要的布局重新生成一个便宜的值，避免搬运原结果。

| 方面 | Task 26 之前 | Task 26 的增量 |
| --- | --- | --- |
| 候选不足 | 已有有限候选求解及失败诊断 | 增加结构化失败分类和独立快照重试，仅可证明空域触发扩展 |
| 转换位置 | 已有显式转换和基本清理 | 增加受限的 elementwise/extend 前移、线程内循环不变转换提升 |
| 重计算共享 | Task 24 已能选择受限重计算，也能共享转换 | 多个 use 可以共享一次选中的重计算，成本与实际克隆均只算一次 |
| 优化安全 | 已有求解计划核验、事务式物化 | 独立转换优化器也在副本上改写，验证成功才替换原程序 |

因此，Task 26 不是重新实现 MMA、Reduce 或 Copy 的布局推断，而是完善候选失败后的处理，以及合法布局方案的后续优化。

## 2. 受控重试：补候选，不放宽正确性

### 2.1 哪些失败允许重试？

“没找到布局”有不同原因，不能一律通过放宽限制继续编译。

| 失败情况 | 例子 | 是否触发候选扩展 |
| --- | --- | --- |
| 可证明的空候选域 | 某变量没有可用的普通候选，且未发现其他阻塞原因 | 可以 |
| 硬约束冲突 | 同一值被要求使用两个不兼容的固定布局 | 不可以 |
| 证明未知或规则不支持 | 无法证明 alias 地址一致或 ownership 正确 | 不可以 |
| 搜索预算耗尽 | 尚未搜索完就达到状态数上限 | 不可以 |
| beam 搜索不完整 | 部分分支被丢弃，剩余分支没有解 | 不可以 |
| 输入非法、成本计算失败 | 图不变量损坏，或无法计算要求的成本 | 不可以 |

区别在于：**候选没有准备够，可以尝试补充；程序矛盾、证明不足或搜索没做完，不能冒充“只差一个候选”。**

显式布局、SameLayout、alias 地址、线程数、写入者、向量硬要求和实际分配容量都不会因重试而改变。

### 2.2 具体例子：为 32 个元素准备有限复制布局

回归 `SM90BoundedReplicationIsARealVerifiedCandidate` 构造如下输入：

```text
变量 v：tensor<32xf32>
活跃线程：32
当前普通候选域：空
没有禁止复制的额外硬约束
```

处理过程为：

1. 普通尝试返回 EmptyDomain，确认不是硬冲突或未知证明。
2. 进入 Replication 阶段，从原始图复制出独立尝试。
3. SM90 目标生成有限的复制布局提案；本例包括 replication 为 2 或 4 的布局。
4. 对新候选重新检查类型、线程拓扑、覆盖、资源及已有硬约束，再进行传播和成本选择。
5. 返回经过验证的解，并记录阶段、提案数量、选择结果和最终成本。

以 replication=2 理解其含义：32 个逻辑元素对应 64 个物理承载槽，即每个逻辑元素存在两份承载。**逻辑张量仍只有 32 个元素，并没有扩大输入尺寸。** 多份持有也不等于允许多个线程向同一地址重复写入；涉及写入的唯一写入者要求仍须单独证明。

这是一项人为构造空域、使用真实 SM90 encoding 和目标验证器的机制测试，不表示普通 `tensor<32xf32>` 程序本来就没有默认布局，也不意味着普通程序一定会进入复制重试。

### 2.3 五级顺序不等于五种新硬件能力

调度顺序固定为：

```text
Replication → Padding/窄向量 → GuardedRagged → TMAFallback → WGMMAFallback
```

当前实际范围是：

- Replication 新增有界提案：每个适用变量至多四个，寄存器位数相对最小值增加 1 或 2，承载槽总数不超过 65536。
- 已有 padding/向量宽度、guarded Copy、TMA/cp.async/vector 仍在普通候选中竞争，不先删除它们来人为制造失败。
- 不扩容实际 allocation，不削弱显式向量要求，不由通用扩展器修改 MMA/Reduce 联合表端点。
- WGMMA 的替代计算路径未实现，最后一级明确记录不支持，不生成虚假的 SIMT 契约。

例如，Task 25 中“对齐不足，TMA 不合法，但普通 vector Copy 合法”的程序，在普通求解阶段就选择合法 Copy，Task 26 不会把它记成一次新增的 relaxation 成果。

每一级都使用“原始候选 + 本级提案”，失败提案不带到下一阶段；第一个成功阶段返回结果，而不是把所有阶段混合后宣称找到全局最优解。原问题无可行方案时也没有可比较的基准成本，因此记录 `baseline=unavailable`，只报告最终成本，不伪造“增加了多少成本”。

### 2.4 避免空域掩盖真正冲突

实现还补上了联合检查。例如三个变量需要布局一致：

```text
x 的候选：{p, q}
y 的候选：{q, r}
z 的候选：{p, r}

约束：x == y，y == z，z == x
```

逐条看，每条边都有相交候选：分别是 q、r、p；但三者没有共同候选，因此整体无解。

即使旁边还有一个空域变量，也不能据此启动扩展、掩盖这个联合冲突。Task 26 会继续对非空部分做有预算的联合搜索。对于缺少端点的转换，只计算部分赋值的成本下界，不把“尚不能完整计费”误报成最终成本失败。

## 3. 转换提升：把不必重复做的转换移到更合适的位置

### 3.1 具体例子：循环内十次转换变成循环外一次

测试使用 `tensor<128xf32>`，32 个线程，每线程 4 个元素。布局 A 与 B 只改变同一线程内部的寄存器槽顺序，不改变元素所属线程。

例如某线程四个槽位的逻辑顺序：

```text
A：[e0, e1, e2, e3]
B：[e0, e2, e1, e3]
```

优化前：

```text
x 使用布局 A，定义在循环外
acc = init_B
for i = 0 .. 9:
    x_B = convert_layout(x, A → B)
    acc = add(x_B, acc)
return acc
```

每轮转换的都是同一个 x。Task 26 检查：

1. x 在循环之前可用，而且循环中不改变 x。
2. A→B 被证明只是线程内 Register 交换，不需要 shuffle 或 Shared 通信。
3. 循环体没有阻止移动的 memory effect、barrier、未知 region 或硬属性。
4. 移动后成本非劣，实际布局关系仍合法。

满足条件后得到：

```text
x_B = convert_layout(x, A → B)
acc = init_B
for i = 0 .. 9:
    acc = add(x_B, acc)
return acc
```

循环中的转换动态执行次数从十次降为一次；循环参数 acc 和循环结果始终保留布局 B，没有改动它们的 SameLayout 关系。

这说明了优化的语义效果，不是 GPU 加速比。当前静态模型按循环深度使用 `2^depth` 权重，并没有根据此循环十次迭代计算精确运行时间。

如果 A→B 需要线程间 shuffle，或循环里存在 barrier，本阶段保留原位置。标记为 Pure 不代表可以任意移动潜在通信操作。

### 3.2 转换也可以移到便宜操作之前

对于紧邻转换、只有一个 use 的纯操作结果，例如：

```text
原来：y_A = add(x_A, x_A)
      y_B = convert_layout(y_A, A → B)

之后：x_B = convert_layout(x_A, A → B)
      y_B = add(x_B, x_B)
```

两个操作数引用同一个 x，所以仍只需要一次转换。若是两个不同输入 `add(x_A, z_A)`，前移可能增加为两次转换，本阶段不做这种改写。

对于 `extend(f16 → f32)`，也可在满足条件时先转换 f16，再做类型扩展，避免先扩成 f32 再搬运。是否接受由实际成本检查决定，不是见到 extend 就强制重排。

还有一条关键限制：**用户显式指定的结果编码不能被这种优化改写。** 只有原本未编码、由推断选出的结果，才会由物化器在内部授予重写许可；最终输出移除临时授权标记。当前没有新增通用 Tensor broadcast 优化。

## 4. 共享重计算：两个使用点共用一次生成结果

### 4.1 原问题：便宜值可以重新生成，但不能重复克隆

取测试 `SharedRematerializationIsChargedAndBuiltOnce` 的例子：

```text
c = constant(3.0) : tensor<64xf32>
return c, c
```

测试固定当前候选赋值：c 使用布局 A，两个返回位置都要求布局 B。这里“固定赋值”用于隔离边界决策，并不是给常量添加禁止克隆的用户硬编码。

A、B 都是 32 个线程、每线程 2 个 F32 元素，但元素分工不同，需要转换才能直接使用已有的 c。64 个 F32 共 256B。

### 4.2 逐项比较三种方案

| 方案 | 实际操作 | 本例第四成本项 `conversionBytesAndSync` |
| --- | --- | ---: |
| 共享一次转换 | 将 c 从 A 转成 B，两个返回位置共用 | 512 |
| 两个使用点分别重计算 | 分别按 B 生成一份常量 | 256 + 256 = 512 |
| 共享一次重计算 | 按 B 生成一份常量，两个位置共用 | 256 |

本例 A→B 是 shuffle 类转换，模型计入源和目标承载字节：`256 + 256 = 512`；常量重计算按目标输出承载字节计为 256。这里是静态工作代理，不是实际访存流量或纳秒数。

决策过程：

1. 确认 dense constant 属于允许重计算的白名单，且没有禁止改成 B 的硬 seed。
2. 确认两个 use 同源、同目标布局、同基本块，能在第一个 use 前生成共享结果。
3. 比较共享转换、逐 use 修复和共享重计算。前面的成本字段在本例不改变决定，第四项 256 严格小于 512，因此选共享重计算；完整九维成本仍按字典序比较。
4. 计划为两个 use 记录同一个 leader，即“负责生成共享结果的边”，并记录相同切片和插入位置。
5. 物化时只克隆一次；第二个 use 直接复用已生成的 SSA 值。

最终效果：

```text
c_A = constant(3.0, layout=A)   // 物化时保留原 producer
c_B = constant(3.0, layout=B)   // 只生成一个克隆
return c_B, c_B                // 同一个值，不是两个相同值的独立定义
```

测试验证了第四项成本为 256、没有 `convert_layout`、只新增一个常量，并且两个返回操作数确实是同一个 SSA 值。

### 4.3 相比 Task 24，具体多了什么？

Task 24 已有共享转换和各 use 的受限重计算。本例在“共享转换 512”与“分别重计算 512”之间持平，保留不克隆的转换方案。

Task 26 新增“共享重计算 256”这一组级方案，所以这次决策发生变化：**不是为每个消费者重新生成一次，而是生成一次后共享。**

另一个测试让同一个常量供 `add(c,c)` 和 `mul(c,c)` 使用，共四个 use。结果同样只克隆一次，四个操作数共用同一个新值，成本仍为 256。

共享仍有限制：最多 8 个不同操作的便宜纯切片；叶子依赖必须在插入点可用；需要的叶子布局转换也必须计费。不同源、不同目标布局或不同基本块不合并，不扩展到任意 MMA、Reduce 或带副作用操作的重计算。成本持平时不因“可以克隆”就强行克隆。

## 5. 三项能力如何配合？

实际处理顺序可概括为：

```text
收集约束、准备普通候选
  → 普通传播与求解：同时考虑转换/重计算边界成本
  → 若失败：分类；仅可证明空域进入独立快照重试
  → 得到合法布局赋值和选中的边界计划
  → 核验计划，在程序副本上物化转换或共享克隆
  → 安全前移/循环提升与转换清理
  → MLIR 和实际布局验证通过后提交
```

共享重计算不是最后随意补的一次优化，它在求解成本中已经可见；转换位置优化则在合法物化之后进行。二者不能互相替代。

例如，将共享计划的第二条边篡改成不存在的 leader，物化器会拒绝，并保留原程序；将转换移到输入定义之前，优化器也会拒绝。这保证“求解时按一次计费”和“程序里确实只生成一次”相符，不能靠少记账得到虚假的低成本。
