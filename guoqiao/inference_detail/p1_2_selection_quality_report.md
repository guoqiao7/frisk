# P1.2 布局选择质量实验报告

日期：2026-10-26。**状态：实现、回归、正式实验及独立最终复审完成，Q1/Q2已验收。** 本文只报告当前 Frisk 模型和有限候选域内的选择质量，不是 GPU 性能报告。具体实验契约见[方案 A](../optimize_plan/p1_2_selection_quality_design.md)，全部数据见[原始汇总JSON](../optimize_plan/p1_2_selection_quality_results.json)，原始IR/trace/日志和源码快照见[证据归档](../optimize_plan/p1_2_selection_quality_artifacts/README.md)。

结论：Auto相对Square在9/16组的模型成本更低，但与FullRow在本组原生Store图全部打平；消费者联合选择出现3个严格geometry反转、6个局部平局消除。代价是C1/C2的Auto编译耗时约为FullRow的2.25/2.24倍。没有GPU收益结论。

## 1. 要回答的问题

1. **Q1：Auto 与 Square / FullRow / FullCol 有什么差别？** 分别运行真实原生流水线，记录成功率、选中布局、九项成本和编译开销。不同策略可能生成不同候选域，因此另从同一 Auto 准备域出发，只限制 MMA geometry，检查差异究竟来自几何选择还是候选覆盖。
2. **Q2：只考虑 MMA 与联合考虑消费者，会不会选不同布局？** 对同一 MMA 分别接 Reduce(dim=0/1) 和固定编码消费者，比较局部最优 geometry 集合与完整图最优集合。把局部 geometry 放回完整图后，其他布局重新优化，不能拿局部成本直接减完整图成本。

## 3. 结果

### 3.1 正确性与最优性范围

230行全部完成：224个完整图成功、6个局部分析成功；24个固定消费者输入全部通过预验证，24个原生入口探针均按预期拒绝未编码的Convert源。实际IR、外部ABI、完整流水线/文本重放及成本贡献核对通过；原始数据经报告工具重新加载核验，完整性错误为0。

166个oracle中，165个完整穷尽、1个截断：`C6-rs-store` joint在120秒时限截断，访问3886节点、评分846个完整赋值。该行的默认解和当前最好解通过实际验证，但**不宣称它是最优解**。核心要求的26个oracle全部完成，2个native/controlled见证通过；16个直接Store图的native最终成功attempt与controlled准备域全部匹配。

165个完整oracle均未发现默认搜索解与最优成本存在差距。166个oracle见证均通过独立副本重建和实际验证，其中160个完整图做了ABI/流水线/重放，6个local只作局部验证，不能混算。没有失败行携带未验证incumbent的情况。

### 3.2 Q1：Auto与固定策略

四种策略各16/16成功。以同一案例/模式的**完整九项向量**比较：

| Auto相对策略 | 成本更低 | 成本相同 | 成本更高 |
| --- | ---: | ---: | ---: |
| Square | 9 | 7 | 0 |
| FullRow | 0 | 16 | 0 |
| FullCol | 13 | 3 | 0 |

这些是原生policy结果，不将不同准备域的数值对照冒充geometry-only消融；后者另由共同冻结域的受限分支和oracle支持。C6 RS joint的全局最优性仍未证完，即便其原生结果与FullRow相同。

SS模式的工作量首项能直观展示多数差别：

| 案例 | Auto所选grid | Auto / FullRow | Square | FullCol |
| --- | --- | ---: | ---: | ---: |
| C0 | `(1,1)` | 129 | 129 | 129 |
| C1 | `(2,1)` | 514 | 516 | 516 |
| C2 | `(2,1)` | 2052 | 2052 | 2052 |
| C3 | `(2,1)` | 1028 | 1028 | 1032 |
| C4 | `(2,1)` | 516 | 520 | 520 |
| C5 | `(4,1)` | 2052 | 2056 | 2064 |
| C6 | `(8,1)` | 2056 | 2064 | 2112 |
| C7 | `(2,2)` | 516 | 516 | 520 |

C2 SS在全部九项上打平；C2 RS则在第五项分胜负：Auto/FullRow的槽位和520，Square/FullCol为528。**本矩阵没有发现Auto优于FullRow的原生Store例子**；Auto的价值在于把几何作为可联合决策的变量，而不是保证每个输入都胜过某条启发式。

## 4. 具体决策与逐项成本

向量顺序为：`[工作量, sector, bank代理, 转换字节/同步代理, 槽位和, Shared根字节, 副本, 代码量, tie-break]`，按从左到右的字典序比较。

### 4.1 C1 SS：Auto 为什么选 `(2,1)`？

输入是 `128×128×16`、256线程的 `MMA → Store`，两个分支共享同一准备域，只限制 geometry，其他布局重新优化。

| 分支 | atom | repeats | MMA工作量 | 完整成本 |
| --- | --- | --- | ---: | --- |
| `(1,2)` | `(64,64,16)` | `(2,1,1)` | `1×2×2×1×1=4` | `[516,4096,0,0,128,8192,0,0,0]` |
| `(2,1)` | `(64,128,16)` | `(1,1,1)` | `2×1×1×1×1=2` | `[514,4096,0,0,128,8192,0,0,0]` |

选中方案的贡献可逐项相加：

| 来源 | 贡献 |
| --- | --- |
| MMA | 工作量2 |
| Store | 工作量512、sector数4096 |
| init/result 两个Tensor载体 | 每个64逻辑槽位，合计128 |
| A/B 两个Shared根 | 每个4096字节，合计8192 |

Store 的512来自 `64个register位置 × 4个warp × 2个warp-group`；每个发射组触及8个32-byte sector，得到 `512×8=4096`。这里按每次发射分别累加，同一sector被多次触及会多次计数，**不是整个输出唯一sector数，更不是DRAM实际传输字节数**。

因此首项分别为 `4+512=516`、`2+512=514`，其他项打平，Auto选择后者。独立oracle实际遍历283个节点、评分64个完整合法赋值，确认共同域最优geometry集合为 `{(2,1)}`。这说明现有模型偏好哪种指令几何，不说明运行时间下降 `2/516`。

### 4.2 加固定消费者后，转换有没有漏算？

同一个C1 SS，固定消费者为 `(1,2)` 的canonical fragment，再接Reduce(dim=0)和Store。MMA仍可选择自己的布局；实际选择 `(2,1)`，中间保留一次非identity显式转换。

```text
MMA(grid=2,1) → ConvertLayout(target=grid1,2的fragment)
             → Reduce(dim=0) → 固定行主序Store
```

完整成本为 `[16290,32,0,133120,208,8192,31,1,0]`：

- 首项：MMA `2`＋Reduce `16384−128=16256`＋Store `32`＝`16290`。
- 转换项：`(16384个源载体＋16384个目标载体)×4字节＋2次同步×4×256线程`＝`131072+2048=133120`，显式转换只计一次。
- 槽位和：`64+64+64+16=208`；Shared根仍为8192字节；副本代理31；转换代码量1。

较大的转换项不一定改变选择，因为当前字典序先比较工作量，再比较sector，之后才到转换项。这个例子验证“消费者约束和转换费用进入完整图”，**不是消费者使geometry反转的例子**；是否反转须检查所有相关分支与最优集合。

槽位和不是实际寄存器峰值，Shared根总量不是occupancy；bank项为0也不表示已证明MMA的Shared访问无冲突，当前该访问成本尚未覆盖。这些差别正是后续P1.3要明确的口径。

### 4.3 C2 RS：消费者确实让最优geometry反转

`M=128,N=512,K=16,threads=256`，RS MMA后接自由布局的 `Reduce(dim=0) → Store`。完整joint与两个geometry受限分支均已得到完整oracle且默认解等于oracle。

| 选择范围 | `(1,2)` | `(2,1)` | 选择 |
| --- | --- | --- | --- |
| 仅MMA：A/init/result槽位和 | `16+256+256=528` | `8+256+256=520` | `(2,1)` |
| 加Reduce结果后槽位和 | `528+64=592` | `520+128=648` | `(1,2)` |

仅MMA时，两种geometry的工作量都为4，Shared均为16384字节；RS的A在 `(2,1)` 中需要更少槽位，因此局部最优集合为 `{(2,1)}`。加入Reduce后，`(1,2)` 投影得到的结果载体少64槽，抵消A多出的8槽，完整图槽位和反而少56。

完整图两分支的前四项相同：工作量 `4+(65536−512)+128=65156`、sector128、bank0、转换0。首次差异出现在第五项：

```text
joint / 固定(1,2)：[65156,128,0,0,592,16384,32,0,0]
固定局部最优(2,1)：[65156,128,0,0,648,16384,63,0,0]
```

完整图最优集合为 `{(1,2)}`，与局部集合不相交，并严格优于“固定局部geometry、重新优化其余布局”的分支，因此这是**严格geometry反转**。原因是当前模型的结果载体/副本代理，不是已测出的Reduce通信延迟或GPU加速。

相同C2但SS模式，局部两种geometry在全部九项上打平；加入Reduce(dim=0)后才选出 `(1,2)`。这一种应叫**消除局部平局**，不能与上面的RS严格反转混为一谈。

## 5. 编译开销

在正确性实验和全部测试结束后，串行运行 Release `frisk-opt`：C1/C2 的 SS × 四策略，每配置 1 次预热、5 次测量，共48次，全部成功。每配置6次的输出IR、转换/重计算计划及非计时统计一致。测量包含解析、完整流水线、IR输出及必需统计，不包含oracle/trace/profile。

| 配置 | 5次测量中位耗时/秒 | 5次测量中的最大峰值RSS/KiB |
| --- | ---: | ---: |
| C1 Auto | 5.9343 | 91680 |
| C1 Square | 2.6381 | 91512 |
| C1 FullRow | 2.6383 | 91848 |
| C1 FullCol | 2.6379 | 91500 |
| C2 Auto | 21.8734 | 190168 |
| C2 Square | 9.7637 | 189580 |
| C2 FullRow | 9.7832 | 189420 |
| C2 FullCol | 9.7925 | 189328 |

Auto增加了编译成本，不能只报告较低模型分数而隐藏这一点。它在本矩阵原生Store图上没有胜过FullRow，因此简单固定图是否需要Auto应权衡；消费者可能改变赢家时，联合选择的价值由Q2展示。

这只是本机CPU全CLI观测，没有CPU隔离、随机交错或统计显著性承诺；父进程5ms轮询，RSS为Linux每子进程峰值。固定策略之间约0.01秒级的差异不作排名结论，所有原始样本保留在JSON。

最终回归：Debug新增20/20（四分片，XML确认20个唯一测试，无跳过），Release新增20/20，原有MMA/流水线24/24，Python/真实CLI集成25/25。此前P1.2的505 unit/69 lit是历史证据，不冒称本轮又执行了一遍；本轮生产include/lib与实验开始快照相同，新增范围是独立实验支持库、脚本、测试和CMake注册。逐任务复审和整体源码复审无未关闭的重要问题；正式正确性证据及第4节算例也已独立核验。

保留两个分析边界：oracle最后一个不评分的拒绝/Unknown分支缺少末尾deadline复查，虽然不虚构穷尽证明，但超时记录可能不够保守；`support_complete`只表示当前Proven支持表，不证明未入表的所有指令替代方案均不合法。工具在默认求解失败时也可能保留尚未物化的oracle候选作为诊断，不能据此作实际IR结论；本轮主矩阵没有这种失败行，实际核验标志齐全。

本阶段只新增实验工具，不修改生产成本权重或搜索预算。没有自动 tile、线程数、流水级数搜索，也不据此证明相对 TileLang/Triton 的性能优势。Q1/Q2 验收后继续 P1.3a→P1.3b→P1.3c；当前尚未实施 P1.3。
